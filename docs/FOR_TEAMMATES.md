# callguard: guide for the sprintd_zurich team (and your coding agents)

This branch holds **callguard**, the second prototype for the Inventx/Outcept case, next to `main` (Kev pipeline +
Gradio dashboard). It is meant for comparing the two approaches without rerunning anything: all code, docs,
research notes and a snapshot of every result we computed are here.

## Architecture in short
audio -> Whisper large-v3 Swiss German (gcoli MIT, faster-whisper) -> Standard German transcript with timestamps
-> diarization (sherpa-onnx) + advisor/customer roles (LLM) -> checks: keywords (the case list, editable),
patterns (spoken digits, codes), **facts** (atomic yes/no/unknown questions read by an LLM via log-probabilities,
decided by an officer-editable rule table `config/policy_table.yaml`) -> fusion (threshold, review band,
uncertainty) -> passages + snippets with reasons -> sinks (result.json, Outcept trigger API, routing/notify, audit)
-> Streamlit officer UI (`callguard ui`, internal) and demo app (`callguard demo`).
Everything is a plugin (`type: "module:Class"`), configured by YAML profiles in `config/`.

## Key numbers (95% bootstrap CIs over twin groups; n is small, overlapping CIs = no detectable difference)
- Case dev (48 calls): champion (Qwen2.5-7B facts, table v1) flag AUC 0.87, false alarms 14%, missed 15%;
  table v3 0.92 / 14% / 8%. The tuned question wording is dev-fitted: reworded 0.72, blind table 0.73.
- Kev-4B as the facts reader: dev 0.86 (reworded 0.90, blind 0.85: robust to wording), false alarms 0-5%, but it
  never answers "unknown", so the review rules do not fire (review recall 0%) and it returns no passages.
- Qwen3.8-27B (3-bit and 6-bit GGUF, llama.cpp): dev 0.85, reworded 0.87, blind 0.83; also no "unknown".
- Your 15 general questions (max p(yes)): Qwen 7B 0.72, Kev 0.79, Qwen3.8 6-bit 0.86 on dev; without a rule
  layer they over-flag (false alarms 27-68% at the CV threshold).
- **test50** (external, never tuned on): champion v1 0.80 (FA 35%, missed 22%), champion v3 0.83 (FA 35%,
  missed 13%, review recall 75%), Kev facts 0.85 (FA 11%, missed 46%, review recall 0%), Kev general 0.75.
- Evidence hit rate: the champion's first passage lands on an annotated "Belege" turn in 73% of correct flags
  (chance 24%).

## Results snapshot (`callguard_results/`)
A copy of our `runs/` trees from the laptop and both GPU hosts: per experiment `summary.md` / `summary.json` /
`spec.yaml`, per variant `rows.json` (per-call labels, scores, CV), `metrics.json`, `meta.json` (exact config,
model ids, cache keys), and `results.jsonl.gz` (full per-call results: transcript segments, every check's output,
facts with probabilities, passages, reasons). No audio, no models, no caches. Datasets are kept apart:
`experiments/` + `perturbed/` = the case calls, `test50/` = your set, synthetic text sets under `experiments/synth_*`.
Never pool numbers across these folders (`src/callguard/datasets.py` refuses to).
Read one call: `zcat callguard_results/experiments/kev_vs_facts/champion/results.jsonl.gz | head -1 | python -m json.tool`.

## Running it
`uv sync --extra asr --extra diarize --extra ui --extra dev`, then `uv run callguard --help`.
Offline (no models): `uv run callguard batch -c demo-offline`. With the snapshot as `runs/` the UIs work offline:
`uv run callguard ui -c recommended` (internal, 8501), `uv run callguard demo -c recommended` (demo, 8502).
Plug in a fine-tuned Kev: serve it with `scripts/remote/serve_kev.py` (set `KEV_MODEL`), then
`uv run callguard experiment experiments/kev_vs_facts.yaml --variants kev_facts` (dev) or
`experiments/test50.yaml --variants kev_facts` (test50, once per candidate, logged in the prereg look log).
